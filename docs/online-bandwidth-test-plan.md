# 带宽优化分阶段测试方案

日期：2026-11-14 起。依据：[优化方案](online-bandwidth-optimization-plan.md)、[开发约定](development-guide.md#8-测试验收与证据)。O1→O2→按证据进入 O3→O4；各阶段的软件门槛通过后再推进。结果以[执行记录](online-bandwidth-test-results.md)为准，本文登记要求和方法。

## 1. O1：完整无损协议

先比较相同完整消息的 JSON、固定 schema JSON 和专用二进制，保留全部输入与本人状态。加强原 `tests/protocol/messages.test.mjs`，验证完整 8v8、缺失/null/false/0/负零、Unicode、数值范围、版本、掩码、截断和长度；未知字段不得静默丢弃。

复用原客户端预测/全武器重放、服务器历史与 Outbox 用例。检查编码不修改权威对象、解码对象拥有独立嵌套值、下一包和不同接收者不覆盖在途缓冲。通过累计、工程/构建和受影响浏览器检查后，依据真实流量决定是否进入 O2。O1 不单独要求达到整体带宽目标，不新增永久用例。

## 2. O2：公共数值与事件

先按实际消息分类定位开销，再处理公共连续数值和射击事件。输入、本人完整校正、时间、分支敏感的 speed/fwd/crouchK/dt 保持精确；射击原始射线、编号和实际表现字段无损保留。审查客户端消费者后，普通广播省略 inputSeq/display/reused/path/reason；服务器权威事件仍完整保留五个回溯诊断字段，并在既有 Outbox 用例验证源对象未被修改。

公共连续数值事前登记：单字段误差≤0.00001，位置每轴≤0.5 mm，实际命中盒各顶点最大偏差≤2 mm。原姿态规则对照仍保持 1e-9；另用真实编解码后的值比较所有命中盒顶点，覆盖 0.3/-0.3/0.5/0.01 阈值内、处、外及插值中间状态、完整一秒死亡动画，不通过调宽原断言使测试通过。显示和服务器历史消费同一规范化公共值，历史另保留阵营等 roster 元数据。

复用原协议、历史、Outbox 和 S4-C2，不新增永久用例。包内数值表、变长定点和旋转省略的预采不代表最终机制；候选的保留/删除依据见执行记录。

## 3. O3：有界压缩与确认基准

完整状态在有效持续负载下仍超预算，才进入本阶段。最终采用稳定公共字节布局、公共 XOR 差量和独立 raw DEFLATE 块；私人校正始终完整。公共几何及动画 phase 使用 1/65536 网格和固定 int32，越界/负零按有界 float32/float64 回退；公共计数、时间和分支敏感值固定 float64。保留全部四元数分量。量化与几何上限沿用 O2，不改变核心或死亡算法。

服务器使用 Node 原生 zlib level=6、memLevel=4；浏览器解码使用锁定的 fflate 0.8.3。单块原始≤2048 B，压缩不划算时同格式存原块；总展开及外层消息均≤131072 B。固定输出长度加一个检测字节，拒绝解压溢出、截断、非法结构和非有限值。原协议用例用独立 zlib 双向对照，不能仅靠自编码自解码证明格式正确。fflate 为 MIT，在线页面和服务器产物带许可；模块例外只允许 `src/protocol/blocks.js` 导入 `fflate/browser`。

公共体和相同已确认基准的差量在房间内复用，组合私人校正时复制到独立消息缓冲；不使用复用池。压缩同步完成，无压缩任务队列；WebSocket PMD 保持关闭，不依赖扩展协商。

基准合同：

- 全量建立初始/恢复状态，后续任何完整重建并提交的 offer 也可成为候选。每个差量明确携带 baseSeq，只相对客户端已确认的 active，不相对未确认的上一包。每约 500 ms 和生命周期必要边界另发独立全量。
- 每连接 active/offered 最多两份公共字节，每份≤128 KiB；未确认的 offered 不被滚动覆盖。onSent 只证明交给发送接口，尚不能使用它作差量基准。输入或现有时钟脉冲携带独立 baseAck，不复用输入 ackSeq 或真实显示引用。
- 客户端完整解码、配对/成员校验并提交后才确认。看到基于 offered 的新包或下一 offer，才证明服务器采用前一候选并释放旧 active；普通显示缓冲的 FIFO 不得淘汰这个基准。数量不随网络延迟增长。
- 房间/成员和阶段边界 reset 全量并清理旧基准；死亡/复活第一包全量，确认往返中可保留旧 active 字节作压缩字典，完整重建结果覆盖当前生命。字典不参与角色身份、历史或预测判定。离场、结束、关闭清空两端。
- 缺基准时公共/私人整包均不应用；一次 resync 等待 reset 全量≤3000 ms，每次加入最多两次恢复，超时或再次失败退出。恢复后建立新的插值边界。请求只重置该连接，不重置其他连接或房间。

新增 **1 条**客户端永久用例 `O3-C1`，独立验证 pin、切换、容量/释放、显示 FIFO 淘汰后的保留、缺基准原子性、请求次数、时限及配对失败。它属于新增协议状态机，不能合理塞入原上行积压用例；累计从 198 增至 199。协议、服务器 Outbox、实际 app 生命周期、几何仍加强原用例，不另增重复项。

```sh
node scripts/run-tests.mjs --layer=client --case=O3-C1
node scripts/run-tests.mjs --layer=protocol
node scripts/run-tests.mjs --layer=server
npm test
npm run check
npm run build
```

O3 必须完成累计、工程/构建、完整语料与两玩法浏览器（含真实全量恢复请求）后才进入 O4。缺基准检测由 O3-C1 固定输入验证；浏览器直接请求全量，避免周期全量先修复缓存使故障触发随机，不要求正常自愈必须额外发 resync。

## 4. O4：联合验收的固定门槛

2026-11-15 用户将性能保障范围调整为：单房最多10真人，或最多两房合计10真人以内。此前两房32真人不再是必须保证的容量点。房间仍可选择4v4/5v5/8v8，机器人补满空位，真人数不等于总角色数。容量准入配置与性能保证分别记录，现有默认2房/32连接不自动视为32真人性能保证。

本次只变更人数范围，以下每连接带宽、有效同步、新鲜度、CPU、队列和恢复门槛保持。原弱网差异来自两真人场景，仍在新范围内，不能因人数目标下调而改判通过。

以下门槛在正式 60 秒候选测量前登记，不能根据结果放宽。KB/s 为十进制 socket 字节，包含 WebSocket 帧；首次握手/创建另列，页面下载、IP/TLS/重传不混计。

| 指标 | 正常本机门槛与依据 |
| --- | --- |
| 每人下行 | 完整窗口均值和非重叠约 1 秒窗口 p95，60/30 Hz 分别≤125/75 KB/s；沿用优化目标 |
| 每人上行 | 均值及逐秒 p95≤10 KB/s，两档输入仍 60 Hz |
| 有效同步 | 每人不同常规运行态 tick 的成功配对应用≥59/29.5 Hz；按档位步距过滤，额外发布/阶段包/心跳不补足 |
| 新鲜度/停滞 | 状态年龄 p95≤50 ms、p99≤100 ms；最长无有效状态≤150 ms，约原 30 Hz 的 1.5/3/4.5 周期；另比较相同工具的原始基线，候选分位不得超过基线加一同步周期 |
| 正常突发 | 每连接逐秒峰值≤250/150 KB/s；整房/进程总量按实际真人数乘算，当前合计最多10人。创建首至少 1.1 秒累计每连接≤250000/150000 B，作为更严的加入突发约束 |
| 消息/缓存 | 编码与展开≤128 KiB；两端基准≤2份、≤256 KiB；旧基准和在途消息不被改写 |
| 排队 | 沿用 256 KiB 停止追加、2000 ms 持续积压终止，重要队列≤128条/64 KiB，上行停止线64 KiB；记录开始/结束的在途量。允许一次有界消息越过 socket 停止线，不把它当成无界队列 |
| 加入/恢复 | create/join 请求到完整配对状态≤3000 ms；正常一次请求，基准恢复单次≤3000 ms，最多两次/加入；不无限重试 |
| 慢连接隔离 | 两房混合正式窗后暂停一个接收 TCP；受损会话按既有6秒新鲜度线退出，观察允许150 ms调度余量；其他连接仍满足同档同步/年龄/间隔线，连接释放后继续推进 |
| 本地 CPU | 总步进 p95≤12.5 ms、p99≤16.67 ms、实际步进≥59 Hz、事件循环 p99≤33.33 ms；沿用 S5，非目标机承诺 |
| 生成器 | 输入≥55 Hz、事件循环 p99≤33.34 ms、迟到回调<2%；不足单列为无效负载，不据低流量判通过 |

当前容量测点：单房10真人+6机器人、两房各5真人+11机器人、两房分别1真人+15机器人和9真人+7机器人，另补两房各1真人+15机器人，覆盖进程内30个AI上界，均用8v8作为角色总量的压力边界。每档各1个60秒窗口，共8窗；接近门槛或波动异常才追加。单房1真人+15机器人及规则/协议/回收/浏览器证据按实际影响复用，不重复旧16/32真人矩阵，也不新增永久用例。偏斜分配覆盖一个机器人密集房和总量上限；原S5-R1验证单真人房关闭后其他房继续推进，不穷举1—9的每种分配。小于10真人的保证不能仅凭“连接更少”推断，结合这些AI边界与既有证据评估。

旧12窗及追加窗属于此前容量范围的历史结果，保留在实施记录，不冒充本次10真人直接测量。原始JSON参考用于编码收益和已登记弱网相对比较；新的正常容量点按每连接绝对带宽、质量和CPU门槛判定，并附加核对原同环境同档基线年龄加一周期的限制；旧16真人基线只作保守参考，不将不同人数样本作同负载性能比较。原始动态轨迹随调度不同，跨运行差值不表示逐帧相同报文的精确压缩比；表示大小另由S3-E1同消息语料比较。

每窗预热≥5秒、采样≥60秒，不强制 GC。不同角色相位在出生区内运动、真实开火/自动换弹；备弹耗尽时提交合法 loadout，不直接改弹药。每真人每完整10秒≥10次权威射击，60秒每人≥2次实际换弹。人数不足、提前结算、停发、耗弹空转或生成器不足标为无效窗口并保留原因。两房混合记录真实伤害、死亡和复活，不以出生区真人样本冒充集中死亡。测量结束结算尾窗与剩余工作，不把推迟到窗外算节流。

```sh
node scripts/s5/run.mjs --case=S5-E1 --hz=60 --humans-per-room=10 --sample-ms=60000 --warmup-ms=5000 --out=artifacts/online-bandwidth/new-single
node scripts/s5/run.mjs --case=S5-E1 --hz=30 --humans-per-room=5,5 --sample-ms=60000 --warmup-ms=5000 --out=artifacts/online-bandwidth/new-two
node scripts/s5/run.mjs --case=S5-E2 --out=artifacts/online-bandwidth/new-resources
```

两房混合窗后通过实际leave/create/join建立相同人数与玩法的新房，预热5秒后单列8.5秒接收暂停和释放片段，避免60秒交火后合法比分结算被误判为网络停滞，记录健康连接、真实队列、基准/内存与恢复；不并入正常带宽窗口。1+9分配中受损者是首房唯一真人，该连接释放后首房应关闭、另一房继续，不能要求空房保留。单房10真人窗后请求一次全量，记录实际恢复。S5-E2两档各24次生命周期的既有结果按影响复用。

累计复核含 S3-E2 两档17个传输配置、S4两玩法、受影响 S2 交火60/30 Hz、打包启动和离线产物。backlog 只在独立命名空间将受损服务器 socket 的 SO_SNDBUF 请求为16384 B（内核实际32768 B），使更小报文能到达真实应用背压；不改宿主/命名空间 sysctl、生产阈值或健康连接。仍用8v8/14个合法尸体，不是玩家击杀证据。

正式弱网补采前固定年龄 p95/p99/最大有效接收间隔（ms）：rtt0 为50/100/150，rtt50为100/150/200，rtt100为150/250/350，rtt150为200/300/400，jitter为250/500/750，loss为500/1500/2000，interruption为1500/2000/3000。前四点按配置单向延迟加调度余量；后三点包含 TCP 重传及已登记3秒恢复边界。健康端始终用50/100/150；slow/backlog 的受损端要求既有策略退出，不能冒充正常有效同步通过。限速下服务器应在6150 ms观察余量内断开；客户端若先达到6秒状态年龄/接收间隔则按原规则退出（允许150 ms调度余量），若有效排队样本仍未陈旧而先触发时钟策略，则必须记录恰好8个未完成请求、最老请求7900—8150 ms，并证明当时状态年龄/接收间隔均未越过6150 ms。不能要求未成立的状态超时先于合法时钟超时；这不改变任何生产阈值。限速/背压观察延长到9秒覆盖原时钟策略，其余配置仍8秒。增加分布采样，不用末尾单点年龄代表全过程。原始源码用同工具对照 rtt0/rtt150/loss/interruption 两档及60 Hz jitter，共9点；其余纯延迟中间点只补候选，避免全组合重复。

测试与实验分别计数，未知选择非零失败，种子/来源/时钟/参数留档，finally 清理。容量实验的“执行成功”不等于预算通过，以 `optimizationAccepted` 和逐层指标联合判断。CPU 重的测量、浏览器、构建串行运行。

证据写入 `artifacts/online-bandwidth/20261114/`。实机、目标服务器与正式 S5/S6 门槛保持；本轮不部署、推送或扩大默认2房/32连接上限。

2026-11-15复核工具计时：短断网从/proc/uptime与25 ms轮询改为Node/Python共享单调时钟与断网期间1 ms轮询，记录tc应用完成时刻。对照与候选使用同一版本工具，原失败保留；门槛和0.9秒断网长度不变。仅复测60 Hz丢包及两档短断网三个有证据的差异点，不扩展无关组合。相对门槛未通过时，O4不能因带宽或绝对指标通过而改判。
