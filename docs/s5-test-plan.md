## 负载与预先判断

S5-E1 只保留两种负载，各在 60/30 Hz 独立运行：高机器人采用 8v8、每房间一真人，递增 1/2/4/8 房间；满真人采用 8v8、每房间 16 真人，递增 1/2/4 房间，最多 64 连接。房间玩法交替覆盖团队竞技/中继。每档递增时，原房间继续真实运行，直接观察创建尖峰；每级预热 2 秒、采样 6 秒。4v4/5v5 的人数正确性由已有 S4 证据及 E2 覆盖，不重复铺设完整负载笛卡尔积。遇到超预算或生成器不足即停止继续加压，保留失败或不合格级别，不以静默减频过关。

本地工程筛选标准在测量前固定：全体房间单步总工作 p95 ≤12.5 ms、p99 ≤16.67 ms；实际步进 ≥59 Hz；事件循环 p99 ≤33.33 ms。前者为 60 Hz 的 16.67 ms 周期保留约四分之一余量。这些是本轮筛选线，不能替代真人体验或宣布正式容量。生成器自身若无法及时提供负载，该级结果标为证据不足，不作为服务器上限。记录实际输入数量、快照数量及双方 CPU，不能把负载缺失误报为低 CPU。

容量覆盖审查补充：高机器人和满真人端点不能证明 MAX_ROOMS=8 与 MAX_CONNECTIONS=64 同时饱和的组合。E1 增加 mixed 负载，两档各只测一个级别：8 间 8v8，每间 8 真人、8 机器人，总 64 连接。新增两次参数运行，不新增永久用例或实验入口；完整矩阵为六个负载/档位配置、最多 16 个级别。此点不合格时保留结果，不把两个单独上限的测量当作联合容量保证。

测量不更改生产模拟、输入频率、人数或队列阈值。强制 GC 只在回收检查点执行，不在 CPU 计时窗口强制 GC。逐配置记录操作系统、CPU、内存、Node、构建、配置和负载；原始明细有硬上限。应用字节与 TCP socket 字节分开，均不伪称包含链路头和重传的线速。

S5-E2 保留 24 轮 × 两档频率，轮次是回收观察的重复，不另算独立通过项。每轮经过实际协议与核心状态迁移；每六轮做一次回收采样，保留自动 GC 和检查点强制 GC 的区别。不凭一个堆大小数字断言没有泄漏；结合可达对象、实例队列和活动资源检查。长时间压力、目标服务器和真实公网带宽仍需另行取得证据。

回收轨迹按同一规模连续两轮排序，再切换人数与玩法，确保实际 OnlineSession 也走过成员版本相同的新房间；这加强原 24 轮的覆盖，不增加轮数。

## 证据与完成层级

本轮写入 `artifacts/online-s5/20261114/`，包含开工来源、方案、命令、首轮失败、测量报告、最终源码差异及归档。先完成本地软件验证和可复现的目标机工具；收到目标服务器与设备条件后，按同样方法执行目标机与真实体验验收。
