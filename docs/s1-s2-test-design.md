# S1、S2 测试覆盖审查与必要补强设计

日期：2026-11-14。状态：已实施；逻辑与五个浏览器场景已执行通过，结果见[执行记录](s1-s2-test-results.md)。下方覆盖审查保留设计时的证据基线和新增理由，旧记录不代表本轮结果。

依据：[开发约定第 8 节](development-guide.md#8-测试验收与证据)、[阶段范围](online-implementation-plan.md)、[技术方案](online-technical-design.md)。历史结果分别见 [S1 记录](s1-test-plan.md)和 [S2 记录](s2-test-plan.md)。历史累计 186 项通过是旧一轮证据，不表示本设计已执行。

## 1. 范围与数量决策

只审查 S1 共用交火链路和 S2 单房间 4v4、M4、机器人、同步及会话实现。实机本轮暂缓；真实弱网、容量、完整大厅和多武器产品流程仍按后续阶段处理。

先复用已有直接证据，再加强不足的断言。本轮新增 **3 条独立用例**：胜利当步停止后续角色、在线输入转换、客户端中断与暂停请求边界。其他缺口安排为 **S1 的 1 处加强、S2 的 7 组现有测试补强**。组内涉及的原用例和参数变体下文分别列出，不能将“组数”当作用例数。

新增的理由均来自已确认需求：现有离线结束流程不覆盖新的 `CombatMatch` 胜利调度；原触摸状态测试不覆盖 `collectInput` 的在线协议转换；核心阶段测试不覆盖 `OnlineGame` 的中断与暂停请求策略。把这些职责塞入原用例会混淆被测层，因此单独设计。

六类产品场景作为覆盖目录：完整交火与成员变化、时间安排与预测、显示与命中、状态切换、异常隔离、最终产物与离线。它们不各自扩张成一整套重复测试。

## 3. 共用约束与独立执行设计

- 逻辑步长固定为 `1/60 s`，默认种子 `4207`。S1 沿用原样本的姿态相位和武器种子；规则随机与视觉随机分开。离散数据、弹药和事件次数精确相等，纯数学对照容差 `1e-9`；浏览器不做逐像素相等或实际耗时毫秒级相等断言。
- 每条独立建立角色、队列、时钟及消息序列；真实服务使用 `127.0.0.1:0`。状态准备可设置初始位置、比分或血量，被测开枪、输入消费、阶段切换和退出必须调用真实代码。客户端单测不启动 `server/app.js`，HUD、DOM 和传输出口可用最小替身，不能替换输入、预测或会话算法。
- 新增及加强项的实际结果见执行记录。统一入口已支持严格选择、按层运行及浏览器场景选择；选中项未执行时失败，空文件占位不算通过。
- 已有名称的独立运行方式记作 `N(文件, 完整名称)`，展开为 `node scripts/run-tests.mjs --file="文件" --case="完整名称"`。N1～N3 也支持 `--case=S2-N1` 等稳定编号；原有完整名称保留，工程探针用例改名映射见执行记录。
- 新增 `tests/client/` 前，确认递归发现仍覆盖该目录，并将其加入 `scripts/check.mjs` 的分组检查范围。文件路径不决定全部责任归属，例如历史 `tests/server/combat.test.mjs` 中的纯核心阶段检查仍归共用规则；本轮不为整理目录批量搬迁。
- 构建可以在一轮中复用，但须核对来源、配置与清单；浏览器单场景自行启停服务和上下文。只清理自身资源，成功、失败和超时均清理，Windows 身份遵循 AGENTS。逻辑项默认执行超时 10 秒，真实服务项 15 秒；浏览器就绪上限 90 秒、单次流程等待上限 10 秒、清理上限 5 秒，超时直接报告原因，不自动重试掩盖失败。
- 输出按用例编号与运行编号隔离到 `artifacts/s1-s2-test-review/<run>/<case>/`，至少记录构建、种子、关键 tick、输入确认、生命/阶段、射击/事件和状态差异。环境不可用、跳过、未选中不算通过；保留首轮失败证据。

## 4. 三条有明确缺口的新用例

### N1 / S2-N1：比分获胜的当步停止后续角色

- **责任与目标位置：** 共用规则；`tests/sim/s2-match.test.mjs`。目标名称 `S2-N1 winning shot stops later actors in the same tick`。
- **依据与新增理由：** 到目标分提前结束、结算一次。现有到时测试不检查比分触发，原离线 `Game` 的结束测试不运行新的 `CombatMatch` 调度。
- **初始状态：** 默认目标 50，BL 比分 49。用真实核心创建 A、B、C 三个真人测试角色，明确本步遍历顺序 A、B、C；A 属 BL，B 为敌方，C 存活且本步也具备射击条件。A、B 在实际地图无遮挡近距离射线上，B 血量设为 1、保护为 0；武器均已准备。初始状态准备不算击杀证据。
- **操作与检查点：** 同一固定步给 A、C 有效开火输入，由 A 的真实 M4 射击击杀 B。随后再调用若干核心步和重复结束请求。
- **独立预期：** BL 从 49 到 50；A 扣 1 发并记 1 次击杀，B 记 1 次死亡；结束事件恰好一次、原因 `score`。C 的弹药与射击编号均不变化，证明不是仅靠 B 已死亡而碰巧没有第二次动作。结束后的时间、比分与战绩保持不变。
- **独立运行：** 落地后以目标文件和上述完整名称选择；不启动网络或浏览器。失败输出实际动作顺序和事件序列。

### N2 / S2-N2：在线输入归一化与边沿只消费一次

- **责任与目标位置：** 客户端；`tests/client/online-input.test.mjs`。目标名称 `S2-N2 online input normalizes movement and consumes edges once`。
- **依据与新增理由：** 键鼠和触屏进入同一种输入帧，斜向不加速，一次性操作不重复。旧触摸状态测试不调用在线入口 `collectInput`，预测测试直接构造输入，均无法发现转换错误。
- **初始状态：** 朝向 0、灵敏度 1、FOV 比例 1；W+D、按住开火，并有一次开火、跳跃、换弹边沿；触控最初归零。采样前后保存演员的位置、弹药和比分。
- **操作与检查点：** 在同一固定轨迹中采样首次键鼠输入、相同按住状态的下一帧，再释放键鼠并用触控提供同方向移动及新的开火/跳跃边沿，最后再次采样。这是 4 个连续检查点，不藏入额外参数循环。
- **独立预期：** 朝向 0 时世界方向为 `(1/√2, -1/√2)`，模长为 1；两种输入来源一致。按住开火继续为真，开火边沿、跳跃和换弹仅在相应新边沿出现一次。第 4 次采样加入一次越界俯仰增量，检查输出限于 `[-1.5,1.5]`；鼠标与触控视角增量被消费。实际协议校验接受组装后的输入消息；采集本身不移动角色、不扣弹、不计分。
- **独立运行：** 落地后按目标文件和名称选择；调用真实采集器、`consumePressed` 实现与协议校验，输入装置用数据夹具，不启动服务或 WebGL。

### N3 / S2-N3：本地中断与全场暂停的请求边界

- **责任与目标位置：** 客户端；`tests/client/online-controls.test.mjs`。目标名称 `S2-N3 local interruption and global pause keep separate request scopes`。
- **依据与新增理由：** 失焦、后台或竖屏只清本人输入，玩家明确暂停才请求全场暂停；恢复等待权威阶段。核心阶段用例和离线清输入用例不验证这些在线请求，现有浏览器也不能独立验证客户端策略。
- **初始状态：** 在线客户端处于 running，键鼠与触控有按住状态，预测有未确认输入。使用真实 `OnlineGame` 方法、`Prediction`、`OnlineSession` 和编解码；DOM/HUD/摄像机表现及 WebSocket 出口用最小观察替身。快照从符合当前协议的确定性夹具提供，预期请求独立写出，不运行真实服务端。
- **操作与检查点：** 本地中断 → 本地继续 → 新的明确全场暂停操作 → 接收成对的 paused 快照 → 请求恢复 → 接收 countdown → 接收 running 快照。阶段消息交给实际接收链路，不能通过直接设置目标阶段冒充状态应用。
- **独立预期：** 本地中断只产生清输入的 `interrupt`，不产生 `pause`；本地继续不产生服务器 `resume`。旧边沿、按住状态和未确认预测被清除。明确暂停产生全场暂停请求；全场恢复只发出请求，客户端在 countdown 期间保持不可操作，直到权威 running 快照才继续。各检查点不重复发送或复活旧动作。
- **独立运行：** 落地后按目标文件和名称选择；每次建立并恢复自己的设备替身与会话，观察真实编码后的消息，不修改被测方法。

## 5. 优先加强现有用例

### E0：S1 导航查询缓冲隔离

复用 `N(tests/sim/s1-core.test.mjs, shared layout preserves all 447 original colliders and gameplay metadata)`。在现有两个实际地图实例中，交错规划已知可达路线；核对另一实例的搜索代次和工作缓冲未被修改，并核对两次相同请求返回同一有效路径。保留原 447 碰撞体和元数据对照，不新建地图用例、不重新生成原样本。新增 0 个参数场景。

### E1：输入执行预算与缺帧沿用

复用两条：

- `N(tests/server/input-queue.test.mjs, arrival never moves time; one input per step and discard frontier advances only on consumption)`。
- `N(tests/server/combat.test.mjs, held automatic fire gives each real bullet a fresh shot number with its original input/display reference)`。

第一条保留重复目标步、确认边界与边沿检查，用独立夹具检查输入年龄 **249、250、251 ms**：前两者仍可沿用按住状态，后者归零；边沿始终不能重放。年龄采用精确整数毫秒，避免浮点 tick 换算把边界问题混入此断言。原 251 ms 场景保留，新增 2 个必要边界变体。

第二条保留实际固定步和每发关联，记录每步实际输入来源与规则时间，按 M4 的 `60/700 s` 冷却和有效步序列独立推导射击数：原夹具 `readyAt=0`、第 1 步开始开火、输入覆盖最初 250 ms 时，发射步为 1、7、13，共 3 发，弹匣从 30 到 27。扣弹、射击事件与编号必须一一对应。输入失效后继续推进一段时间，射击数不再增加。重复或集中提交不能直接产生额外模拟步。到达安排改变但执行输入序列相同时结果一致；输入被作废时不强行与未丢输入的结果相等。此项验证应用输入策略，不声称 WebSocket/TCP 会重排消息。

### E2：完整本人恢复、重放与生命周期

复用两条：

- `N(tests/net/prediction.test.mjs, full save/restore and real M4 replay preserve RNG, recoil, ammo and hit-response state without repeated effects)`。
- `N(tests/net/prediction.test.mjs, unpaired corrections fail, and stage/life transitions discard pending actions)`。

第一条的确定轨迹延长至 240 个固定步：第 30、60 步各开火一帧，第 90 步换弹；夹具中无外部伤害和额外目标。初始 30/90，明确检查射击后 **28/90、shots=2、shotSeq=2**，换弹完成后 **30/88**。在换弹完成前后各保留检查点，不能只检查“开始换弹”。短步态、蹲姿和已有受击弹簧继续参与恢复；每 10 步提供同边界校正，保证重放窗有界。

保留两端状态比较，同时直接读取关键演员/武器字段、随机状态、受击偏移和反馈计数，预期键不能从 `saveActor` 自动枚举：否则两端遗漏同一字段仍会通过。每次重放期间新增声音/特效回调为 0；正常预测恰有两次开枪与一次换弹反馈。数学状态沿用 `1e-9` 容差。

第二条覆盖实际配对接收失败、阶段变化，以及同一角色死亡后复活为新 lifeId 的连续轨迹。核对失败快照不部分更新客户端状态；死亡/新生命不重放旧 pending 或 held。保留原序号错配，补充 own.actorId 错配这一独立身份条件，新增 1 个拒绝变体。角色更替和断线后的新身份由 E4 验证，不在此复制房间实现。

### E3：历史判定必须产生可区分结果

复用 `N(tests/server/history.test.mjs, client display and history use exactly the same endpoints/alpha and finite fallback windows)`，以及 `N(tests/server/shots.test.mjs, valid history reconstructs an actual hit; expired/missing references fall back to exactly one current shot)`。

实际射击场景保留现有 4 个引用变体，但把目标从历史样本中的射线位置移动到当前射线之外，生命、队伍和保护状态不变。有效引用必须历史命中并产生一次伤害；无引用、缺样本和过旧引用必须当前判定且不命中。**四种情况均正常扣 1 发、产生 1 个 shotSeq，不能因补偿不可用取消有效射击，也不能先历史命中再补当前判定。** 这能发现“总按当前”或“总按历史”的错误；原场景两条时间线都命中，区分力不足。

历史资格检查增加“较小端点未发过、较大端点已发过”的发送空洞，保留另一端点未发过的原变体，新增 1 个发送资格变体。回溯年龄分别取窗口上限的 `-1/0/+1 ms`：60 Hz 为 199/200/201，30 Hz 为 249/250/251，共 6 个必要配置边界变体。为单独验证总上限，夹具 RTT 设为 200 ms，使连接约束不先拒绝；输入创建时间取当前时钟，保证输入本身有效，不将显示引用年龄与输入年龄混为一谈。这只是时间资格输入，不是弱网体验实验。原正常引用也承担窗内基线。

保护与生命检查复用已有两条用例。旧生命引用失效后，如果当前新生命无保护且恰在当前射线上，规则允许本次当前命中；不能把“旧历史不得转移伤害”错误解释成“新生命永远不能被当前判定击中”。

### E4：真实服务的成员替换与释放

加强 `N(tests/server/app.test.mjs, application import is inert and repeated close releases the actual HTTP/WebSocket room lifecycle)`。

使用临时真实 HTTP/WebSocket 服务、受控单调时间和两个协议客户端。检查 0→1→2 真人、A 离场补机器人、A 以新连接重新加入、最后真人离场的同一生命周期。任一活跃房间始终 8 个角色；替换使用新身份和出生状态，B 的身份与战绩不被重置。为检验继承问题，可给离场者设置初始非默认血量、弹药、战绩及未来输入；这些仅作生命周期夹具，不能当作交火证据。

核对公共/本人快照同序号、本人数据绑定对应连接；原角色、未来队列与旧连接不能继续推进或计分。最后离场后 room 为空，关闭后连接、历史、定时任务和监听释放，重复关闭安全。等待实际服务端关闭事件，不使用固定睡眠猜测。现有单客户端场景改为这一条双客户端轨迹，不再保留重复单人副本。

### E5：协议拒绝只影响对应连接

加强 `N(tests/protocol/messages.test.mjs, protocol accepts bounded inputs and rejects forged identity, extra actions and non-finite fields)`，以及 `N(tests/server/app.test.mjs, version mismatch, invalid action, size and rate limits reject the offending real connection)`。

纯协议用例分别改变 protocol、build、rules，一个字段错也必须不兼容；原 rules 变体保留，新增 2 个字段变体。原非法字段、非有限数和 JSON 复杂度检查保留。

服务端沿用现有版本、非法动作、超大及超频 4 类错误连接，同时保持一个已入房正常连接 A。使用默认频率上限，仅让超频连接超过它；不能沿用较小上限却让正常连接的检查消息也超频。每次拒绝后通过 A 的实际 clock/有效输入和配对快照，确认它仍可交互、确认边界继续推进、角色未被重建；错误连接未加入或已被正确清理。复用原 4 个拒绝场景，不增加模糊随机报文或不同编码的大规模排列。

### E6：同房快慢连接、配对替换与有限积压

加强 `N(tests/server/outbox.test.mjs, one slow peer replaces complete paired snapshots, preserves important order and terminates sustained backlog)`。

以实际 `SampleRoom`、`Outbox`、编码和输入消费运行，一个传输出口正常、另一个可控地报告积压。网络出口替身只控制 readyState、bufferedAmount、send 和 terminate，不替换房间或队列算法。正常连接每步仍可消费有效输入并收到同边界快照。

慢连接先阻塞 10 个固定步，再恢复，核对只发送最后一份完整配对快照，重要消息仍按序，未实际发送且仍在历史中的样本不进入发送资格集合。再次阻塞，检查持续时间等于上限时尚未提前结束、超过上限 1 ms 后被结束；正常连接与房间继续推进。现有恢复后再持续阻塞的轨迹保留，增加的是同房观察与真实消息断言，不新增另一套相同慢连接用例。队列字节/数量上限复用原第二条用例。

本项只证明应用层隔离与替换策略。真实 TCP 限速、丢包、重传、容量和内存长期趋势仍待 S3/S5，不把出口替身结果升级为真实网络结果。

### E7：已有浏览器场景独立运行并加强结果

把 `scripts/s2-browser-check.mjs` 中已有覆盖整理成三个可独立选择、自建自关的场景：

| 目标场景 ID | 主要目的 | 独立初始状态及通过条件 |
| --- | --- | --- |
| S2-I1 在线交火 | 实际输入与权威反馈连接正确 | 两会话加机器人；固定合法站位，各自执行同一段移动、开火和换弹操作，分别记录本人预测、权威实际执行及对方收到的结果；不是只让高帧率一方操作。弹药与 shotSeq 对应、命中和比分来自服务器，换弹完整完成；反馈重放不重复 |
| S2-I2 暂停恢复 | 任意成员请求能更新两端 | 两会话均已入房，A 实际操作暂停，B 实际操作恢复；双方冻结，3 秒倒计时不延长，恢复必须看到权威 running，旧按住输入不复活。使用真实请求和时间，不把 resumeAtMs 改到过去来证明恢复成功 |
| S2-I3 触摸中断 | 实际触控进入在线输入并正确释放 | 横屏新会话，原生浏览器触摸移动/开火；保持接触时转竖屏、再横屏继续，旧接触不重新生效，服务器对局不被本地转屏暂停；新触摸可重新操作，最后退出并释放 |

这三个场景是已有覆盖的执行结构拆分，不宣传为新增功能覆盖，也不把一个总脚本算作三条均可独立执行。实施后的脚本已支持这些 ID，每次运行自行建立和关闭服务及上下文。

I1 采用 3 个有名称的运行配置，避免无目的地展开所有组合：A=`60 Hz / 120 FPS 上限`，B=`60 Hz / 30 FPS 上限`，C=`30 Hz / 30 FPS 上限`。A/B 比较渲染安排，B/C 比较同步安排；实际帧率写入证据，不要求机器恰好达到上限。若实际高低节拍未形成对照，帧率对照项标记环境不满足，不能只凭设置上限宣称覆盖。每种配置重建相同种子与场景，以双方实际执行的输入和固定步时间比较规则预算，不按浏览器睡眠毫秒数要求位置严格相等。规则结果预期由固定操作与独立模型给出，不回填当前实际轨迹。

I2、I3 默认 60 Hz；不在每类错误和每种设备尺寸上重复三档运行。此前 30 Hz 触摸等结果可按构建适用性复用，不能将未重跑的组合标为本轮新通过。总计 **I1 三配置 + I2 一配置 + I3 一配置，共 5 个浏览器执行场景**，均在报告中单列。

## 6. 独立选择与实施次序

当前已有 Node 用例可按完整名称和文件选择，例如：

```powershell
node --test --test-name-pattern="^full save/restore and real M4 replay preserve RNG, recoil, ammo and hit-response state without repeated effects$" tests/net/prediction.test.mjs
node --test --test-name-pattern="^application import is inert and repeated close releases the actual HTTP/WebSocket room lifecycle$" tests/server/app.test.mjs
```

以上原生 Node 命令不负责零匹配失败判断，实际独立执行应使用统一入口 `node scripts/run-tests.mjs --file=文件 --case="完整名称"`；单条、整层和全套命令见 [README](../README.md#运行)。浏览器用 `--case=S2-I1|S2-I2|S2-I3`，I1 可选 `--profile=A|B|C`，缺浏览器明确失败。S1 离线独立方式为：

```powershell
node scripts/s1-browser-check.mjs --file dist/offline/harbor-after-rain.html --out artifacts/s1-s2-test-review/<run>/S1-offline
```

执行前先构建或核对当前匹配产物；占位的 `<run>` 必须替换为实际运行编号。真实本地服务及浏览器使用同一桌面用户。

实施顺序：先落实选择、命中校验和清理约束并复用现有失败探针验证入口；其次完成 E0～E6 及 N1～N3 的低成本逻辑检查；最后改造 E7 和复验最终离线产物。若已有用例可合理承载新需求，进一步合并本设计中的新增项；没有新的明确缺口，不继续增加用例。

新增 3 条是当前设计决策，不是总条数目标。E1 的 2 个新年龄变体、E2 的 1 个身份拒绝变体、E3 的 1 个发送空洞与 6 个配置边界变体、E5 的 2 个兼容字段变体都单列成本；E7 的 5 个场景也单列。其他固定轨迹中的检查点不伪装成额外独立通过项。实施后按实际执行单元报告数量，不能直接将历史 186 加 3 当作新验收结论。

## 7. 完成判断与保留缺口

本设计只有在目标用例落地、每项可单独复现、实际执行并保留失败/通过证据后，才更新对应覆盖为直接验证。运行时核对来源及最终产物；失败先找根因，不通过放宽命中数量、误差或时间条件消除失败。

本轮仍不验证：真实设备触控/焦点/声音与网络体验、真实弱网及容量、长期资源趋势、完整大厅和其他武器玩法。S1 现有强证据保留，S2 也不据此标为全部体验验收通过。旧会话关闭回调刻意迟到等额外交错尚无独立反证，不宣称已穷举；后续仅在明确风险或缺陷证据要求时扩展。

本文件保存覆盖设计、3 条新增用例定义、既有用例补强清单、独立执行约束和明确未验证项；实际通过数、首轮失败、实施调整与归档路径单独记录在[执行记录](s1-s2-test-results.md)。
