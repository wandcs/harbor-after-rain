日期：2026-11-14 起。状态：S1—S4 软件与自动化已有通过记录，S5 已完成[本地检查](s5-test-results.md)，实机与目标服务器未验，未进入 S6 整体验收。随后按用户安排完成规则配置统一、[独立交付包准备](release-package-results.md)及[本地启停与回退演练](local-runtime-results.md)。带宽优化的实现与联合门槛见[优化执行记录](online-bandwidth-test-results.md)，后续测量与时钟修正见[弱网前两步记录](online-weak-network-test-results.md)；O4 相对弱网未通过项保留，进一步性能优化按用户安排暂缓。不能把本地软件检查写成正式容量、体验或发布通过。

2026-11-15用户收敛性能验收范围为单房最多10真人，或最多两房合计10真人以内；旧16/32真人测量保留历史，不作为当前必须保证的容量。带宽、同步、CPU和弱网门槛保持，直接结果见优化执行记录。

目标是在现有游戏中实现[联网产品设计](online-product-design.md)，保留原有枪战规则、键鼠与触屏操作及离线单 HTML。机制依据为[技术方案](online-technical-design.md)，执行与完成标准遵循[开发约定](development-guide.md)，发布遵循[发布与运行约定](release-runbook.md)。

## 1. 阶段推进规则

用户已确定：分阶段独立实现、独立设计测试方案，保持测试通过后再进入下一阶段。

“独立”指每阶段有明确范围、可运行交付和自己的验收证据；后续阶段在已通过的实现上继续，不复制规则或另建长期分叉。

2026-11-14 针对既有 S1/S2 的[测试覆盖审查与补强设计](s1-s2-test-design.md)已实施，累计逻辑 189 项和五个独立浏览器运行通过；[执行记录](s1-s2-test-results.md)单列证据与未验证项。实机按用户要求暂缓，当时停在 S2。

随后用户明确要求继续 S3：沿用实机暂缓安排，开始 [S3 自动化实验](s3-test-plan.md)，保留 S2/S3 的实机与体验缺口，不将它们记为已通过。此授权调整本次工作顺序，不撤销体验及发布验收条件。

S3 已完成两档编码对照、17 个真实传输配置与对应修复；累计逻辑 189 项、五个浏览器场景及离线回归通过。具体结论和剩余退出条件见 [S3 执行记录](s3-test-results.md)，当前不推进 S4。

每阶段按以下顺序执行：

1. 开工前按[开发约定的测试规则](development-guide.md#8-测试验收与证据)核对现有覆盖和新增必要性，细化本阶段测试方案，列明场景、责任层、输入与随机种子、预期结果、独立运行方式、环境、设备、网络条件及证据位置。下文给出各阶段的必需范围；实际测试文件与命令随对应实现落地。
2. 确认进入条件，记录起点的提交及未提交差异。保留用户工作，不将已有失败算作本阶段通过。
3. 按可验证的小步实现，测试实际共用代码和真实调用链。发现失败先定位原因，不删除有效断言、降低验收标准或用替身掩盖回归。
4. 运行本阶段必需检查及累计回归，单独检查最终差异，补齐文档与证据。
5. 全部退出条件满足后记录结果，再自主进入下一阶段，无需逐阶段重复确认。未执行、跳过或缺少设备的必需检查均不算通过。

自动化基线包括 `npm test`、`npm run build`，以及 S1 交付后的 `npm run check`；浏览器、真机和网络检查按本阶段实际影响选择。旧阶段的有效覆盖保留在累计回归中；用例合并、替换或去重遵循开发约定并保留需求映射。必要的体验检查在受后续改动影响时复验，不机械重复无关测试。

若后续改动破坏已通过阶段，先修复并重跑受影响检查，再继续推进。缺少必需设备、真实丢包环境或目标服务器时，停在当前阶段并记录缺口，可以继续准备当前阶段所需工具和材料，不能跳到后续产品实现。技术路径失效时按开发约定重新审视问题；改变已确定产品或支持边界时再讨论具体方案。

## 3. S1：共用交火链路与工程检查

**目标与范围。** 先选现有 M4（`m4a1`），提取真实地图布局与碰撞、角色移动、必要武器状态、射击起点与方向、命中姿态、伤害和少量机器人依赖。时间与规则随机源由宿主提供。原离线入口实际调用提取后的计算，其他功能暂按现有调用保留，不建立第二套枪战规则。

同步交付递归测试发现、锁定版本的 Prettier/ESLint、循环依赖与模块边界检查，以及本阶段所需浏览器脚本的 `CHROME_PATH` 和受测地址配置。检查工具明确新模块和修改文件的覆盖范围；现有目录的未迁移代码明确列出，不宣称全仓已符合目标边界。`npm start` 继续静态预览。

**进入条件。** 已有开工评估；开始改动前确认测试和构建起点，记录浏览器及离线行为基线。

| 测试组 | 方法与预期 |
| --- | --- |
| 检查入口 | 临时嵌套测试中的真实失败必须使 `npm test` 失败，恢复后正常通过；验证检查工具能报告格式、静态规则、循环与越界导入的违规样例，临时样例不留在产品中 |
| 无设备运行 | 在未提供 DOM、WebGL、材质和声音设备的 Node.js 进程中创建并步进实际核心；模块导入不启动监听或循环 |
| 地图与移动 | 对照原有通道、楼梯、高台、出生点、下蹲、跳跃和碰撞；同规则、输入与种子下比较位置、速度和状态，数值容差在测试方案中说明 |
| 武器与伤害 | 覆盖开火、连射、换弹、切枪、弹药、散布、后坐力、受击偏转与出生保护；核对射击起点、方向和头胸四肢命中盒，不只比较参数表 |
| 离线真实入口 | 浏览器真实键鼠完成移动、开枪、换弹、受击、暂停恢复与重开；对照提取前行为；构建后的单 HTML 在断网且无服务器时打开并游玩该链路 |
| 回归 | 累计逻辑测试、构建和检查入口通过；改动触及的现有玩法、触控和展示场补对应检查 |

**退出条件。** 上述必需检查通过；Node.js 与原离线入口复用实际计算，射击和命中行为无未经批准的改变。基线、对照结果、命令和限制均有记录。

## 4. S2：最小联网对战

**目标与范围。** 接入最小单房间权威对局，保留 M4 和机器人。交付 `protocol`、可创建和关闭的服务端应用、在线/离线明确入口、输入消费、公共与本人快照、预测重放、远端插值、射击编号、有限回溯及暂停恢复。建立诊断字段和有限配置初值。此阶段即设置输入、事件、历史与发送队列上限，S3 再按弱网证据调整。

**进入条件。** S1 通过。用户在 2026-11-14 明确调整执行顺序：先完成实现和自动化，设备稍后提供；两台真实设备仍是本阶段退出条件。按实际核心依赖列出本人状态字段，逐项说明权威恢复或重推导方式，形成协议校验与测试用例。

| 测试组 | 方法与预期 |
| --- | --- |
| 协议与服务生命周期 | 版本不兼容、非法与非有限字段、消息大小和频率上限明确拒绝；导入 `server/app.js` 不占端口，临时服务与连接可释放、重复关闭安全 |
| 输入与预测 | 用确定输入序列验证实际执行/作废确认、完整状态恢复和重放；迟到不加速，边沿不重复，校正不重复扣弹、发声或计分；覆盖双人对撞、挤通道和掩体边缘 |
| 快照与事件 | 公共与本人状态只按同一快照边界应用；新事件先到不额外修改远端真人或机器人的命中骨骼，本地预测反馈仍有效 |
| 射击与回溯 | 静止/移动目标、头胸四肢、下蹲跳跃、遮挡穿透及出生保护；对照实际显示样本和服务器重建姿态；连射每发绑定实际输入与引用，机器人按当前权威状态射击 |
| 引用与生命周期边界 | 未同步、样本被清理、引用过旧或超窗时，有效射击只按当前状态判定一次；过期输入及错误身份、生命、阶段作废；死亡、复活和暂停不复用旧操作或历史 |
| 双设备交火 | 两台真实设备实际移动、射击、换弹、与机器人交火及暂停恢复；不同渲染帧率下操作时间预算一致；手机参与时同时观察触控和横放路径 |
| 回归 | 累计自动化、构建、检查入口和受影响离线链路通过 |

**退出条件。** 实际双设备交火及上述正确性检查通过，诊断能够关联输入、射击、生命、阶段与显示样本。连接成功和同机标签页仅作辅助证据，不能替代本阶段体验验收。

## 5. S3：弱网与同步验证

**目标与范围。** 在 S2 样例上验证 WebSocket 是否适合试玩目标，比较同一份完整必要状态的 JSON 与简单二进制，验证 60 Hz/30 Hz 两档及配套缓冲、回溯和队列初值。补充实验与诊断工具，不先添加复杂差量、自动降档或第二套传输。

**进入条件。** S2 通过；网络注入方法能影响实际传输链路，双设备仍可交火。每轮先写明变量、对照、样本持续时间和判断方法；校正、停顿和主观手感的判断依据由样例基线细化，不事后修改标准让结果过关。

| 测试组 | 方法与预期 |
| --- | --- |
| 两档与弱网 | 两档均覆盖 RTT 0/50/100/150 ms、抖动与真实丢包，记录注入方向和实际测量；用移动目标与掩体对射观察命中、校正和停顿，覆盖 TCP 重传影响 |
| 输入中断 | 连射途中缺输入、短时断网、后台与恢复；输入过期停止沿用，恢复不集中补走或补射；显示引用失效走确定回退路径 |
| 慢连接隔离 | 单客户端限速或积压时，其他成员继续交火；公共快照与本人校正成对替换，各类队列有界；持续失效连接按规则结束并补机器人 |
| 编码对照 | 相同完整必要字段做往返、字节量和编解码耗时对照；量化时验证头部、楼梯、高台和掩体边缘精度；公共编码复用不漏本人校正和事件开销 |
| 诊断与回归 | 记录真实出网、RTT、快照间隔、队列积压及持续时间、校正幅度、超窗回退比例和步进耗时；累计测试、构建、检查入口与 S2 关键交火场景通过 |

**退出条件。** 实验记录能说明样例的可用网络范围和当前限制，并据此确定样例使用的编码、缓冲、回溯、输入新鲜度及队列参数。固定 60/30 Hz 两档不变，最终服务器容量在 S5 确定。若传输持续影响玩法，先按技术方案的进入条件重新评估，不能以继续堆产品功能代替方向验证。

## 6. S4：完整产品流程

**目标与范围。** 补齐全部现有武器、刀与手雷、团队竞技与中继争夺，以及房间列表、创建、密码、容量、分队、配装、成员更替、断线和结算。共用核心拥有对局状态，房间只管理接纳与连接；完成完整在线/离线会话装配。

**进入条件。** S3 通过，联网交火机制可用于扩展；按产品流程逐项设计正常、竞态与失败路径测试。

| 测试组 | 方法与预期 |
| --- | --- |
| 房间接纳 | 4v4、5v5、8v8，一真人立即开局且机器人补满；密码、满员、已结束、最后空位并发、资源准备后状态变化；分队和替换在同一边界生效 |
| 成员生命周期 | 创建者离开不影响其他人；真人替换机器人和离场补位均从出生点开始，不继承个人状态；断线按新玩家重新加入；旧生命消息不影响新角色；最后真人离开释放全部资源 |
| 暂停与本地中断 | 任意真人可暂停/恢复，3 秒倒计时不被重复恢复延长，新暂停可取消；暂停期间仍可加入和离开；菜单、失焦、后台和竖屏只清本人输入，旧输入不跨阶段复活 |
| 武器与玩法 | 全部武器、近战、投掷、配装与复活；已投手雷在投掷者离场后保留原归属；两玩法到时先结算、提前胜利、平局、据点轮换及完整对局；结束流程只执行一次 |
| 列表与结果 | 真人数不含机器人，暂停和剩余时间正确；结算显示在场角色战绩并关闭房间，返回列表无需新建连接；失败原因明确 |
| 双设备与离线回归 | 实际操作完整创建/加入/退出流程及两种玩法；离线单 HTML 断网复验完整玩法、键鼠、触控和原暂停体验；累计测试、构建和检查入口通过 |

**退出条件。** 产品设计的全部行为有实现和对应通过证据；S2、S3 的预测、命中和网络检查在受扩展影响的范围内复验通过。

## 7. S5：跨设备与容量

**目标与范围。** 在目标服务器和实际电脑、手机上验证完整产品；依据 CPU、内存、出网和体验结果确定固定房间/连接容量及最终有限队列配置。测试用部署按任务授权执行，服务器采购或新增付费资源另行讨论。

**进入条件。** S4 通过；已有获授权的目标服务器、实际设备和网络注入环境。记录硬件、系统、浏览器精确版本、分辨率、输入方式、构建及配置，容量与体验判断方法在实验前确定。

| 测试组 | 方法与预期 |
| --- | --- |
| 设备与访问路径 | 电脑和手机从实际 IP 页面同场游玩，覆盖键鼠、双拇指、声音、WebGL、鼠标锁定或拖动视角、全屏或手动横放、后台和转屏；30 FPS 与较高帧率玩家规则一致 |
| 人数与网络 | 两种玩法和 4v4/5v5/8v8；两档同步、完整必要消息及 S3 网络矩阵复验，结合真实交火记录可接受范围 |
| 多房间与创建尖峰 | 多个各一真人、其余为机器人的房间，以及已有交火时创建房间；测每房间和全进程 p95/p99/最大耗时、调度落后、事件循环延迟、内存峰值、垃圾回收及总出网 |
| 隔离与接纳 | 一个房间暂停、结算或销毁不改变其他房间状态；查询与导航缓冲隔离；达到固定上限明确拒绝新请求，已有对局继续运行 |
| 资源与离线 | 重复创建/关闭、慢连接和断网后，房间、连接、任务、历史及缓冲释放，资源无持续增长；最终离线构建在无网络、无服务器环境复验 |
| 回归 | 累计自动化、构建、检查入口和受影响体验检查通过 |
