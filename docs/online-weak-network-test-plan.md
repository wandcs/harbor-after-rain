# 弱网测量与时钟修正：前两步测试设计

日期：2026-11-15。用户已授权执行[方案](online-weak-network-optimization-plan.md)的前两步。先完成W1测量校准，再做W2运行逻辑；不实现发送窗口，不修改现行O4通过线、玩法、未来输入/预测/回溯或退出上限。

## W1：校准测量

复用S3-E2，增加独立可选的接收侧ingress/IFB拓扑，MTU1500并关闭GRO/GSO/TSO；保留原loopback拓扑作对照。能力探测已证明可在一次性网络命名空间内实现，因此采用同进程、共享单调时钟，不另建第二套跨进程驱动。所有应用仍是普通Linux用户，root只做隔离网络设置/观测，退出销毁；不触碰宿主网络。

在原消息处理外围观测回调入口、解码完成、配对提交、预测校正结束，分别报告实际接收/应用年龄、SDK估计年龄及偏移误差。正常常规tick、额外发布、集中交付分列；显示采样记录真实引用、时间倒退和连续held持续时间。实际故障恢复后，记录连续3个不同常规tick回到原正常年龄范围，以及新输入真实执行的时间。新观测不替换旧门槛。

同进程实际年龄以`performance.now()-snapshot.nowMs`核对；完整原始行留档，可从原始行重算分布。采集TCP/TcpExt计数、有限队列观测和实际故障时刻，核对MTU/offload/注入方向、真实丢包与重传。数组与采样有界，观察不能改变原动作或消除不利样本。

W1只跑60 Hz无故障、1%丢包、0.9秒短断网，两个拓扑对照；先不遍历17个配置。两种拓扑均检查健康端、权威移动/开火、无补执行、反馈去重和清理。无新增产品协议字段或永久用例。累计原199项、工程检查通过后固定W1源码/结果，供W2同工具、同拓扑对照。

## W2：时钟/RTT与生命周期

加强现有`tests/net/session.test.mjs`三项和`tests/server/app.test.mjs`连接生命周期项，不增加永久用例：

| 层 | 必需覆盖 |
| --- | --- |
| 客户端 | 孤立大RTT/偏移尖峰不跳变；持续真实RTT增加能跟进；样本过期、迟到/重复/未知回复、单调时间、数量上限与关闭清理 |
| 输入与显示 | 偏移、输入调度、显示延迟用途分离；保留30步未来界与60 Hz输入；150 ms RTT的目标提前量仍足够；实际显示引用不伪造，显示时间不倒退 |
| 生命周期 | 6秒接收/权威陈旧条件不依赖射击或存活，合法暂停仍合法；原8个未完成clock与最多两次基准恢复规则保持，定时器随结束/关闭清理 |
| 服务器 | pong精确匹配ping序号，迟到回复不误用最新ping；重复/未知回复不改变RTT，待确认记录有限、断线清空，原6秒心跳策略不扩大 |

新实现先由上述现有用例取得反证，再修复并累计回归。原始RTT保留诊断，有限窗口选样用于时钟；输入余量与显示时间使用各自有界估计，持续变慢不能被永远保留的最小RTT掩盖。参数在实现中明确记录并用确定输入验证，不根据实验结果临时放宽。

W2实现前固定初值：时钟窗口最多8个样本、有效期8秒，偏移选窗口中最低RTT（同值选新样本）；输入RTT取最近3份的中位数（不足3份取较低中位），显示RTT以1/4权重跟进该值。显示目标时间以正常时间流速的±10%校正偏差，阶段/加入/恢复边界重建；逻辑服务器时间不冻结。会话每100毫秒及输入/采样入口检查原6秒条件。服务器ping负载为4字节序号，待确认最多8份、按原6秒期限过期；只有匹配回复更新心跳和RTT。这些是可复现实验初值，不是新的弱网体验承诺。

W2先用W1固定工具比较60 Hz丢包和短断网；补30 Hz短断网、150 ms RTT检查输入提前量。若单次丢包差异不稳定，最多事前固定3组成对种子、交错执行顺序，保留每轮；不反复重跑挑成功。

运行代码变更后执行累计、工程、构建，两玩法浏览器及受影响交火/恢复。容量只复核一个合计10真人的两房压力点（1+9），两档；明显回归才扩展，不重跑32真人矩阵。共用规则和离线产物未变时以来源/哈希复用已有证据。

现行年龄/间隔、输入超时、回溯和O4相对一周期条件均不变；测量与实现通过不等于O4弱网整体验收。分别报告原估计线是否通过、真实年龄/恢复变化、功能正确性及仍未定位的传输差额。W1/W2完成后才能按数据决定是否进入发送窗口或讨论验收口径，不自动推进。

## 后续：重传恢复与旧快照归因

用户已授权复用丢包/短断网用例查清等待来源，再决定发送窗口；本轮只增强S3-E2观测并补压缩参数勘误。产品运行代码、频率、玩法和验收线不变，不新增永久用例。

先跑60Hz无故障校准包序号与应用字节的映射，再跑60Hz loss、60/30Hz interruption，均ingress、种子4207、原8秒动作与原功能断言，共4窗。除非捕获失败或证据有明确缺口，不追加种子或容量/浏览器矩阵。修改测试脚本后执行工程检查；用独立手算序列核对归因计算，不为诊断新建永久场景。运行代码/产物未变时复用前两步199项和构建证据。

仅在临时命名空间的lo观测端口45931：Python标准库AF_PACKET记录出站TCP包头、内核时间戳、序号、ACK与SACK，不保存业务载荷；检查捕获丢包、数量上限和实时/单调时钟转换误差。出站数据包只证明发出，不能证明交付；接收端生成的累计ACK与SACK证明接收进度/缺口，再与实际客户端应用时刻交叉核对。保留kernel、report和原始头记录，可重算。

测试驱动外围记录每个服务器快照生成、Outbox交付send、实际TCP流字节区间、首次发出及接收确认；不修改帧、动作或发送顺序。用SYN建立字节基准，独立核对WebSocket帧长度和原有socket.bytesWritten，避免将应用send当作接收确认。

短断网分列：tc恢复→缺失字节的后续重发→接收进度恢复/首个完整快照→恢复当时已提交的旧快照排空→连续3个新鲜tick。列出恢复时已提交、已发出、已确认及未应用的快照数/字节。丢包按SACK与累计ACK停顿划分缺口段，关联实际重发及缺口补齐后的旧状态交付；没有证据的等待保持未知，不用“最后一次收包间隔”冒充重传耗时。

恢复后的旧快照排空与重传可能重叠，不能把两段强行相加或把观察到的排空时长当成发送窗口的必然收益。保留TCP确认延迟及应用调度边界；新鲜度诊断沿用零延迟50ms，100ms RTT的loss按单程50ms加同样50ms余量取100ms，仅作归因，不替代旧门槛。发送窗口只有旧状态持续排队被证明占主要可改善尾部时才值得进入；其余情况记录停止理由和下一步建议。
