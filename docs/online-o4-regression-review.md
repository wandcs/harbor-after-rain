## 3. 复用S2-I1验证浏览器恢复

沿用现有S2-I1两人交火和独立M4时间预算、真实伤害/计分、换弹、预测反馈去重等断言；追加可选short-offline片段，分别使用A（60Hz同步/120FPS上限）与C（30Hz同步/30FPS上限）。默认入口不启用该片段，不增加测试编号。

Chrome157.0.8103.78原生WebSocket；CDP在受损页模拟离线约900ms，保留原连接，排队消息在恢复后继续交付。正式片段前用轻量原生WebSocket核实行为，并检查同进程不同上下文及独立进程的故障作用域。能力探测是夹具验证，不计为游戏用例。

Chrome支持WebSocket网络节流；本轮仍以实际能力探测确认具体行为。[Chrome官方说明](https://developer.chrome.com/blog/new-in-devtools-99/#throttling-websocket-requests) **CDP离线不制造内核丢包和RTO退避，不能把下面约70ms与WSL真实丢包后的约800—900ms直接比较。** 本轮不是实机或公网体验验收，也不声称同机浏览器窗口达到了容量实验的全部同步率门槛。

片段准备新的生命和站位，随后都走真实键鼠、浏览器发送、权威输入队列与HumanActor执行：先按住移动/开火，离线期间释放，确认旧开火停止；恢复后按新的移动键，再进行新射击。记录原始帧编号、目标tick、阶段/生命、发送API时刻、服务器收到/作废/实际执行和配对确认；收包或作废ACK不算执行。新操作移动由权威位置变化核对。

浏览器/服务器用5次短往返中最小不确定度样本映射单调时间，保存前后偏移与误差；恢复时刻保留CDP命令开始/完成区间。正式补验两档偏移漂移分别约+0.24/−0.12ms。

## 4. 夹具失败与工程验证

首次网络参考客户端没有后续二进制版本新增的receiveWire方法，三窗均在预热/采样前失败并清理；首批候选三窗结果保留。观测改用两版本共有的原生ws消息入口后，重新登记并完成上述完整三对；没有改参考运行代码或用失败重试选择更好的网络样本。

首次浏览器两档完成交火与恢复采样后，因未关闭时closed未设置而非显式false，被新增观测断言拦住。修正为布尔读取后，各补一次后续断言验证；首轮30Hz的162ms有效不利观测没有被后一次覆盖。另删除未登记、由夹具自行推导的额外状态密度要求：它不是既有S2-I1产品合同；保留原150ms间隔判定。补验增加服务器发布时间，不改变消息、动作或生产参数。

新片段默认关闭，仅接受明确S2-I1的A/C选择，错误选择在启动浏览器前拒绝。新观测模块纳入既有工程检查和浏览器全局声明；不修改全局lint规则来忽略错误。累计仍199项，无新增永久用例。
