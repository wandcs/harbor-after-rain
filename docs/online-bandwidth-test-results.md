# 带宽优化实施与验证记录

日期：2026-11-14—15。依据：[优化方案](online-bandwidth-optimization-plan.md)、[分阶段测试设计](online-bandwidth-test-plan.md)。用户授权开始实现；实机与目标服务器仍暂缓，未进入 S6。

## O1：无损完整协议

O1 软件实现与本阶段必要检查通过，整体带宽目标尚未达到，后续进入 O2。正式协议为 3：输入与完整配对快照使用专用二进制，控制/事件仍为 JSON；浮点保持 float64 精度，整数与布尔精确，未启用压缩、差量或降频。公共部分每房编码一次，组合私人校正时复制到独立缓冲。

字段采用固定 schema、存在掩码、布尔位标志、枚举编号及精确数值表示；未知字段明确报错，不静默丢弃。区分缺失/null/false/0，保留负零和 JSON 可接受的 UTF-16 字符串。浏览器以 ArrayBuffer 接收，服务器区分文本和二进制，JSON 输入/快照不作为第二条正式高频路径。

复用并加强原协议、Outbox、历史姿态和 S4 全武器重放用例，累计仍为 **198 项，未新增永久用例**。现有假客户端改用正式编解码；完整实际状态、尸体和暂停阶段参与往返，旧缓冲与嵌套状态不被后续编码覆盖。

首轮反证为原实现不产生二进制输入，协议组 1 通过/1 失败，保留 `O1-protocol-red`。其后的尸体覆盖断言因测试选中了同队角色而失败，修正为敌方起始目标后走实际伤害链验证，没有降低断言；记录 `O1-protocol-first`。初筛还处理了负零错误归入整数零的边界，并补充初始出生样本和 Unicode 字符串覆盖。

## O2：公共数值与完整射击事件

O1 分类短测中，60 Hz 每人约184 KB/s为快照、58 KB/s为射击事件。公共几何采用有界表示、射击事件完整无损打包；服务器历史使用客户端实际解码值，另保留阵营/昵称/控制来源元数据。输入、本人校正及 speed/fwd/crouchK/dt 等分支敏感值保持精确。

O2 累计198项、工程/构建和浏览器交火通过；必要场景仍未满足全部预算。首次两档短测约146/82 KB/s；包内去重及定点候选进一步缩小，但有效持续交火60 Hz预采最大均值约135.7 KB/s、逐秒p95约158.6 KB/s，不能以6秒短测的较低均值判优化完成。因此按进入条件继续O3。`O2-verified*`、`O2-browser`、`O4-preflight`保留对应过程证据；预采并非最终验收。

## O3：最终协议、压缩与确认基准

正式版本为 **9**。公共几何与动画phase主要为1/65536固定网格，越界/负零保留浮点，单字段误差上限仍0.00001；公共计数、时间、分支敏感值固定float64，输入和本人状态无损。公共字节只相对已确认active基准作XOR，私人校正始终完整；两者同一快照提交。初始、周期、生命周期和恢复提供独立全量。

每端每连接最多active/offered两份基准，未确认候选不滚动覆盖；offer在完整重建并校验提交后才由独立baseAck确认。显示缓冲FIFO不能淘汰正在被服务器使用的基准。缺基准整包不提交，单次全量恢复最多3秒、每次加入最多两次；恢复时重新建立插值边界。服务器相同基准的公共编码按房复用，私人组合复制到独立缓冲。

采用≤2 KiB独立raw DEFLATE块，总展开/外层均≤128 KiB；压缩无收益则同格式存原块。服务器原生zlib level6/memLevel4，浏览器用锁定[fflate 0.8.3](https://github.com/101arrowz/fflate)（MIT）；在线页面及服务器带许可。同步处理，无压缩工作队列，WebSocket PMD保持关闭，支持不提供扩展的连接。没有差量链、缓冲复用池或新的部署服务。

为达到预算而试验过的LZ4、公共数值引用表和四元数省略均已移出正式代码。LZ4与系统liblz4 1.10.0双向63份向量互操作通过，但带宽收益不足；逐小片streaming inflate一度使生成器约10.6 Hz，属于无效负载，没有计作节流通过。最终定长块输出与原生服务器适配解决该CPU问题。500 ms老基准的p95也不够，因此后续完整重建的候选可在确认后推进active，仍不依赖未确认包。

原198项保持，**仅新增1条客户端O3-C1，累计199通过、0失败/跳过**。新用例独立覆盖pin/切换、40帧后显示FIFO淘汰仍保留基准、缺基准原子性、有界恢复及配对失败；其余协议、Outbox、实际app生命周期、姿态/历史及全武器重放均加强原项。协议以独立zlib双向对照，并保留无损全状态严格比较；原规则矩阵对照仍为1e-9，有损几何另用预登记2 mm上限。

## O4：正式联合复核

最终正式结果见本节末表。固定参数见 `O4-final-thresholds.json` 及测试方案；候选每窗预热5秒、采样60秒，使用真实合法运动、开火、换弹和配装补给。原始参考由开工归档解出，只替换测量脚本，按其锁文件隔离安装并构建；不修改参考的src/server。

早期level1取得两档高机器人占比有效窗：60/30 Hz每人平均下行90.3/50.9 KB/s，逐秒p95为108.3/61.4 KB/s，带宽、有效同步、年龄、CPU和负载联合通过。两档原始JSON参考最大每人均值866.9/468.1 KB/s、逐秒p95为1019.8/590.2 KB/s，参考负载有效；这些不是同一逐帧消息语料的精确压缩比。该轮仅作为过程证据，最终同构建结果以下表为准。

2026-11-15 联合门槛修订实现（门槛未放宽）：原 level1 两房32真人60 Hz 的逐秒下行p95为127.77 KB/s，未通过；level6 的30 Hz为75.61 KB/s，未通过；level9 两档带宽均达标，但60 Hz事件循环p99为33.783807 ms，高于33.333333 ms，仍未通过。压缩等级提高不再作为解决方向。恢复level6，将不参与分支判定的动画phase纳入既有1/65536误差网格，并按原方案的消费者审查移除普通shot广播中的 inputSeq/display/reused/path/reason。客户端只读取稳定编号和已解析射线/表现；核心事件及S3回溯诊断保留完整，既有Outbox用例验证源事件未改、其余字段严格相等。协议布局变更升为9，不新增永久用例。正式复测使用新构建与 `O4-v4-thresholds.json`；v1/v2/v3失败窗口保留，不能替代最终通过证据。
慢连接夹具边界修正：`O4-v4-mixed-30` 的60秒正常窗口联合通过，随后的隔离片段失败。服务器记录出现一个end、房间数由2变1、该房全部8个健康连接留在大厅；全局仍60.07 Hz、CPU与另一房同步正常。中继规则达到50分会正常结束，此时运行已约73秒，不能要求同一房继续运行8.5秒。保留这次失败，不放宽150 ms停滞门槛；隔离片段改为通过实际leave/create/join建立相同人数和玩法的新房，再预热5秒。常规60秒窗口不改，生产结算规则不改。新增记录结果消息供后续区分正常结算与传输停滞，两档隔离重新验证。

最终冻结前补齐恢复清理边界：发送resync若因上行积压同步关闭会话，原实现随后仍会创建3秒定时器。先保留旧实现反证 `final-cleanup-red.log`，再在send之后检查closed；既有O3-C1增加该分支，仍共199项。`final-verified-tests.log`累计通过。修复不改变编码或正常发送，构建标识变更后仍重新执行同构建正式窗口；v4中已通过的窗口只保留作过程证据。最终门槛登记为 `O4-final-thresholds.json`。最后一个30 Hz单房正式窗逐秒p95为73.005 KB/s，接近75 KB/s；按测试方案“接近门槛才追加”的规则，事前登记一个相同条件的60秒追加窗，保持全部门槛和负载。它属于必要的稳定性采样，不新增永久用例。
30 Hz slow初次复核失败保留在final-verified-weak：服务器在采样3.845秒按心跳断开，客户端仍接收有效排队样本，状态年龄4.52秒时因8个时钟请求未完成在7.844秒退出。状态陈旧的6秒条件尚未成立，原夹具机械要求状态超时原因不符合真实策略。修正为分别证明服务器心跳、客户端6秒状态条件或8请求时钟条件，不接受任意错误；新增退出时最老时钟年龄及接收年龄观测，故障片段观察9秒。生产逻辑、阈值、正常14配置及带宽测量不变；针对slow两档与backlog复测，原失败不覆盖。
