# 发布与运行约定

版本：1.3。更新：2026-11-16。发布规则自后续开发起使用。

当前 S4 软件与 S5 本地验证已完成（见[S5 记录](s5-test-results.md)）。[独立运行交付包与完整构建清单](release-package-results.md)及[本地启停、重启和回退演练](local-runtime-results.md)已完成对应本地验证；目标服务器、实机体验、正式干净来源构建和目标环境运行演练仍待验。本次未部署，也未将这些准备工作视为 S6 整体验收通过。生命周期与版本规则见[开发约定](development-guide.md)，技术边界见[联网技术方案](online-technical-design.md)。

## 1. 发布单位与授权

首版在一台服务器运行一个 Node.js 进程，同进程提供在线页面和 `/ws`。不引入数据库、容器平台、房间迁移或热更新。进程重启结束全部内存对局，玩家重新进入列表；恢复旧程序也不恢复旧对局。

一个发布包含同一来源的在线页面、服务端、离线单文件、锁定的运行依赖、许可、构建清单、配置摘要与验收记录。单独构建某个目标可用于开发，但不构成完整发布。

代码完成、提交、合并与发布分别记录。发布目标和外部操作必须在任务授权内；已有授权继续有效，不逐条重新确认。公开发布授权不自动包含购买资源、改变账号或删除历史版本。

## 2. 发布前的必备记录

发布时将实际值写入该版本的验收或交付记录。机器相关操作说明放在交付记录或私有部署记录，仓库只保留无敏感性的引用。

| 项目 | 必备内容 |
| --- | --- |
| 来源 | 产品版本、提交、干净工作区确认、锁文件校验值和构建配置 |
| 环境 | OS、架构、精确 Node/npm 版本、CPU、内存与实际出网约束 |
| 运行位置 | 完整交付目录、监听地址与端口、页面和 `/ws` 地址 |
| 进程管理 | 实际启动、停止、重启、自启动、进程状态和日志查看命令 |
| 配置 | 同步档位、房间／连接上限、输入与事件队列上限、超时与慢连接阈值 |
| 验收 | 设备、网络、完整产品场景、容量与离线证据，以及已知限制 |
| 日志 | stdout/stderr 采集位置、轮转配置、保留上限与磁盘检查方法 |
| 回退 | 上一可用完整版本及匹配配置的位置、校验值、恢复命令和演练结果 |

具体 OS、服务管理器、网络注入工具和主机路径在服务器选定后填写，并在目标环境验证。当前不虚构这些值。开放试玩前，这张表不得保留影响执行的空项；不能用其他机器上的测试替代目标服务器证据。

## 3. 构建与产物

正式来源包以干净提交和锁文件构建，使用开发指南确定的工具链。本地验证包可使用未提交来源，但必须如实记录并标为 `build.kind=local`。当前准备与验证命令为：

```sh
npm ci
npm test
npm run check
npm run build
npm run package
```

`npm run build` 生成下表中的完整运行目录及清单；`npm run package` 再生成 ZIP、旁置清单和 `SHA256SUMS`，默认输出在 `artifacts/releases/<运行编号>/`。`node scripts/package-release.mjs --out=目录` 支持指定新交付目录，拒绝覆盖已有文件。`npm run package:release` 要求干净 Git 来源且禁止开发/单目标构建，但该标记只证明来源门槛，不代替体验、容量、运行和发布授权。

| 目标产物 | 用途 |
| --- | --- |
| `dist/online/index.html` | 连接同源服务的在线页面 |
| `dist/offline/harbor-after-rain.html` | 无服务器、断网下可直接打开的单文件 |
| `dist/server/main.js` | Node.js ESM 服务端运行入口 |
| `dist/release.json` | 来源、版本与产物清单 |
| `dist/package.json`、`dist/package-lock.json` | 独立目录的运行命令与仅含 `ws` 的锁定依赖 |
| `dist/verify.mjs`、`dist/RUNNING.md` | 无外部依赖的完整性校验及运行说明 |

`release.json` 至少记录产品版本、提交、构建标识、协议版本、规则标识、Node/npm 版本、锁文件及构建配置摘要、产物相对路径、字节数与 SHA-256。清单不包含其自身校验值；交付记录另记清单及最终交付包校验值，避免循环计算。时间使用带时区的 ISO 8601。

当前 schema 为 1。`source.inputs` 记录实际构建输入的相对路径、字节数与哈希；`source.localChangesSha256` 覆盖这些输入和对应已跟踪 Git 差异，不复制差异正文。源码锁与运行锁在 `locks` 中区分。`build.configuration` 及其哈希记录实际编译选项，选项影响构建标识；`configuration.defaults` 记录无环境覆盖的有限开发配置，部署覆盖值须另记。无 Git 元数据的导出来源只允许标为本地验证，不得伪装为干净正式来源。

交付包携带匹配的 `package.json`、锁文件与运行所需文件；外部运行依赖在交付目录按锁文件安装。不得靠发布机上已有的全局模块运行。保留必要许可和署名，不能把构建机的凭据、原始参考素材或本机配置装入包内。

包采用明确文件白名单，当前为 14 个列入清单的文件加 `release.json`。解包后先核对可信交付记录中的外部校验值，再按包内说明安装与校验。`node verify.mjs` 不需要先装依赖，会拒绝缺失、损坏、混合版本或非清单文件；`node_modules` 是按锁文件安装后的独立运行依赖目录。安装需要 registry 或已有缓存，本包不宣称离线安装依赖。

在线、服务端和离线版本一起核对，离线版还要验证未尝试连接服务器。正式验收使用最终产物；任何后续修改使相关旧证据失效，必须补跑受影响检查。通过版本的离线文件可复制到 `offline/` 形成带版本的下载文件，记录其来源与校验值。

## 4. 发布门槛

- 开发指南要求的评审、检查和对应实际体验验收通过，构建、协议和规则标识一致。
- 产品完整范围已覆盖：两种玩法、全部现有武器、人数选项、机器人补位、暂停恢复、断线、结算及离线交付。
- 电脑和手机在实际 IP 页面同场游玩，声音、输入、横屏及已有兼容路径可用。
- 两档同步和技术方案的网络、命中及生命周期矩阵取得证据；目标服务器容量和队列参数已写为有限配置。
- 没有影响发布范围的 P0/P1 问题，也没有未满足的已确认验收条件。其余已知问题注明影响与可用操作路径。
- 发布清单、运行说明、日志上限、上一版本与回退检查齐备。

只开放单枪技术样例时，必须明确标为技术预览，且任务已有发布授权覆盖该范围，不能据此宣称完整产品验收通过。复用已有证据时注明构建与适用范围；依赖、规则、设备条件或最终产物改变后，重新判断其有效性。

## 5. 部署与启动

1. 检查当前版本、运行状态、活动对局、磁盘和日志，确认发布范围及目标。
2. 将新版本放入独立交付目录，核对包、清单和文件校验值，安装锁定的运行依赖并校验配置。准备失败时不改变当前服务。
3. 尽量在无人对局时切换；需要中断现有对局时，在授权范围内明确说明影响，按既定重启边界执行。不等待无上限的暂停对局，也不增加暂停限制来迁就发布。
4. 停止旧进程，确认它已释放监听端口和资源，再由已验证的进程管理方式启动新版本。不能在运行目录手改文件或混入上一版本模块。
5. 执行部署后检查，通过后记录实际发布时间、操作者、版本、配置和结果。失败则停止扩大试玩并进入故障处理。

仓库运行入口仍为 `node dist/server/main.js`，仓库内 `npm start` 调用该入口。独立包解包后在包根目录按锁文件安装，执行 `npm run verify` 和 `npm start`，其入口为 `node server/main.js`。两种目录使用同一服务端产物。目标发布流程还须记录实际构建、监听地址、同步档位与有限容量，验证服务管理器停止及退出超时。已有本地应用关闭与临时服务释放证据，不能替代目标机运行演练。

本机开发默认绑定回环地址，部署使用明确配置的可访问地址。`GET /health` 返回初始化状态、构建／协议／规则标识，以及仅含名称和版本的 `product`；实际启动入口从该目录的 `package.json` 提取产品信息，不暴露其他包配置。旧版缺该字段时按其完整归档清单核对。健康接口不得暴露密码、连接详情或玩家数据，其响应不代替对局验收。

本地前台可直接运行包内 `node server/main.js`，与 `npm start` 的实际入口一致。前台 Ctrl+C 请求停止；Linux/WSL 自动演练只向本轮创建的确切 Node PID 发送 `SIGINT` 或 `SIGTERM`。入口记录 `Stopping`、释放资源后记录 `Stopped`，正常退出码 0，保留现有 5 秒退出兜底。强杀不计为优雅退出；不能用结束 npm 包装进程代替实际服务进程的停止验证。Windows 子进程信号语义不同，说明见[包内运行说明](../packaging/RUNNING.md#本地启停重启与回退)。

## 6. 部署后检查与运行

部署后检查进程与健康信息、页面构建标识、WebSocket 握手、创建加入与机器人补位、实际移动射击、暂停恢复、退出清理，以及离线下载文件校验值。完整设备矩阵在发布前完成，部署后检查确认交付和实际访问路径有效，不能仅核对进程存活。

旧页面连接新服务时按版本检查明确要求刷新，不静默混入新规则。发布及回退后均检查页面与服务端来自同一发布，避免缓存造成版本混用。

运行时关注进程异常退出、事件循环与调度落后、出网与队列、活动房间和内存、磁盘与日志上限。使用应用已有诊断及宿主基础工具，不要求额外监控平台。运行日志通过 stdout/stderr 交宿主采集和轮转，保留策略遵循开发指南；诊断采样有界，问题结束后关闭。

运行反馈记录版本、设备、网络、操作、预期与实际，按开发指南分级。定期依赖升级另开任务，保留可回退版本，不在故障处理中顺带做无关升级。

## 7. 故障、回退与收尾

启动失败、页面与协议不匹配、跨房间串扰、持续影响玩法的积压或关键产品回归时，先保留有界诊断，再停止相关试玩或回退。普通重启不自动证明问题已修复，不连续盲目重启。

回退使用已归档的上一完整版本及配套配置和运行依赖，核对校验值，按第 5 节的停止与启动步骤切换，再执行第 6 节检查。不能只换页面或只换服务端，也不能把新版本的所有配置未经核对交给旧程序。回退后记录原因、影响对局范围与待修复问题；内存对局不恢复。

至少保留当前和上一可回退版本、匹配配置、发布清单及验收证据。首个联网版本没有上一联网版本时，发布前验证停止联网服务、恢复原静态试玩入口的步骤，并告知其只提供本地机器人玩法；它不算联网恢复。

回退演练在独立端口或独立验证环境执行，不以中断真实试玩作为默认练习。旧版与新版本读取各自配置，独立运行不能共享房间状态。发布和回退工具不顺带删除历史、修改账号、密钥或权限；有此需求时遵循单独授权。

本地复用启动检查的 `--lifecycle` 变体：准备两个完整归档及配套配置，在同一临时端口依次启动旧版、停止并重启旧版、切到候选、回退旧版、恢复归档静态 HTML，最后停止并清理。各次在线恢复均核对健康标识、空大厅和实际输入执行；暂停中的旧对局不恢复。候选校验或配置失败时原服务继续。每次停止后实际重新绑定端口，不能只根据启动日志判断释放。

本轮本地静态回退使用单 HTML 预览工具重现归档入口，核对原 HTML 字节及不提供联网。它没有操作原公开托管服务。实际服务管理器、自启动、长期日志轮转，以及目标机上的同样切换与回退步骤，仍须在部署授权范围内复核；本地结果见[演练记录](local-runtime-results.md)。

当前没有服务器，目标机命令、容量及参数等待对应实施与实测任务补齐。发布规范已确定，这些事实尚未取得；首次开放试玩前须完成实际操作说明和一次可验证的回退演练。
